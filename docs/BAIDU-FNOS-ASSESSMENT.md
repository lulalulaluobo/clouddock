# 百度网盘接入飞牛：验证结果与方案

验证日期：2026-10-25。最初为只读检查；随后经用户明确授权，对指定的 `kongq.mp4` 执行真实转存和完整下载验证，详见末尾补充。

## 结论

建议：夸克继续使用 aria2，百度使用飞牛官方百度网盘应用的下载引擎。CloudDock 统一搜索、勾选、云盘/本地目录选择及任务展示。

当前 CloudDock 产品界面尚未集成百度转存下载，需要新增百度驱动和飞牛下载适配器。通过 NAS 本地验证脚本已成功调用分享转存与官方 NAS 下载接口，具体结果见末尾补充；前面的只读结论保留用于说明验证过程。

## 本机实证

- fnOS：1.2.0800。
- 官方应用：`baidu.netdisk` 0.3.2，维护方百度网盘，发行方飞牛。
- `baidu.netdisk`、`baiduNas`、`P2PClient` 进程运行中，SDK 在本机回环地址监听。
- CloudDock 的 NAS v0.8.3 分发实现支持识别百度资源，但云盘驱动没有百度；新增的一次性本地下载链路针对夸克。
- 官方应用静态前端：`/var/apps/baidu.netdisk/target/static/assets/index-BL6eYgFA.js`。源码明确包含以下调用链：
  1. 根据分享短链接、提取码读取分享列表，用户勾选 `fsid`。
  2. 调用分享转存，携带 `fsid_list`、`to_path`、`device_id` 等参数。
  3. 查询该次转存任务；成功后读取返回列表中的 `to_fs_id`。
  4. 调用 `fileTask/downloadToNas`，传入 `targetPath`、精确的 `fsIds`、冲突处理参数 `rtype`。
- 官方 UI 的该流程默认云盘目标为 `/我的资源`；底层转存请求有 `to_path`，自选云盘目录仍需联调验证。
- 读取 `http://127.0.0.1:5666/app-baidu-netdisk/api/v1/user/info` 返回业务 `code:401, msg:unauthorized`。没有提取用户登录凭据或绕过鉴权。

## 已定位的接口（应用内部接口，不视为稳定公开契约）

| 功能 | 路径（均位于 /app-baidu-netdisk/api/v1） |
|---|---|
| 读取当前账号 | GET `/user/info` |
| 分享信息/文件列表 | POST `/p/apaas/1.0/share/info`、`/p/apaas/1.0/share/list` |
| 精确转存 | POST `/p/apaas/1.0/share/transfer` |
| 查询转存结果 | GET `/p/apaas/1.0/share/taskquery` |
| 下载到 NAS | POST `/fileTask/downloadToNas` |
| 任务列表/详情 | POST `/fileTask/list`、`/fileTask/listDetail` |

请求签名、设备参数、账号授权和任务响应格式应由官方客户端/授权适配层承接；不硬编码或外泄应用凭据，不将 SDK 回环服务直接暴露公网。

## 实施方式

1. 设置页增加“飞牛百度网盘”连接配置和状态。通过正式飞牛授权建立可续期会话，并确认当前账号和会员状态。
2. 百度搜索结果复用原资源选择/转存弹窗，增加百度文件列表、云盘保存目录；飞牛本地路径仍是辅助选项。
3. 新增百度转存驱动：只提交本次所选 ID，保存转存任务 ID，严格使用返回的目标文件 ID，不扫描整个目标文件夹。
4. 新增飞牛下载适配器：映射允许的下载根目录为宿主机实际路径。不能直接把容器内 `/downloads` 当成飞牛接口的宿主机路径。
5. 一次性作业记录保存 `provider=baidu`、`engine=fnos-baidu`、原生任务 ID、用户、目标路径及幂等键；失败重试不重复转存或重复下载。
6. “下载进度”按引擎展示：夸克仍进入现有 AriaNg，百度显示飞牛任务状态/速度/暂停继续。百度任务不会自动出现在 AriaNg 中。
7. 不修改官方百度应用文件，不设置目录定时扫描，不增加 QAS 任务。

## 下载引擎选择

aria2 只负责传输，不会自动继承飞牛百度 NAS 会员权益。即使能取得普通百度下载链接，也不能据此保证 NAS 会员加速适用。继续使用官方应用的下载链路最符合用户现有权益；实际吞吐取决于账号权益、百度服务和网络，需要实测。

百度官方 NAS 方案说明 SDK 可以提供上传下载任务创建和控制能力：
https://yun.baidu.com/union/industrySolutions?type=storage

飞牛官方说明 fnOS 1.2.0800 起提供 AI Agent 授权，并可选择百度网盘权限。这说明存在正式授权方向，但不能直接推断该授权覆盖上述全部内部接口，需要实际验证：
https://help.fnnas.com/articles/v1/settings/authorize

## 尚待验证

## 补充验证：SSH 复用现有授权（2026-10-25）

用户要求先尝试已有 SSH 权限，不重新走 AI Agent 授权。已完成：

- 只读检查官方应用数据库，确认 fnOS 用户 1000 已绑定百度账号，有现存 access/refresh token 和设备绑定。软删除标识为 `0`，不能用 `IS NULL` 判断有效记录。
- 仅在 NAS 进程内存中读取现有 access token，调用百度官方 HTTPS 接口；没有打印、复制到本地或写入报告，也没有刷新 token、重新登录或改变绑定。
- `/rest/2.0/xpan/nas?method=uinfo`：`errno=0`，账号读取成功。
- `/rest/2.0/xpan/file?method=list`：`errno=0`，根目录限量读取 2 项成功；不输出用户文件名。
- `/rest/2.0/xpan/device?method=iotqueryuinfo`（携带已绑定设备 ID）：`errno=0`，`data.is_iot_svip=1`，确认当前飞牛设备的 NAS 会员有效。返回到期时间戳 `1815494399`。
- 普通账号接口返回 `vip_type=0`，与设备 NAS 会员字段不同；不能据此认定 NAS 会员失效。
- Nginx 将请求代理到本地 `/var/run/baidu_netdisk.sock`，转发飞牛会话 Cookie，并清空 Authorization 头。因此现有百度 token 可用于云盘 API，但不能当作飞牛网页会话直接调用 `fileTask/downloadToNas`。

结论修正：**读取当前百度账号、网盘目录和 NAS 会员权益不需要用户重新授权，现有 SSH 可以复用官方应用的有效百度授权。** 后续正式集成应采用 NAS 本地适配层管理凭据，不让 CloudDock 前端接触 token。

验证边界：尚未打通飞牛业务下载接口的会话调用，也未创建任务。现有授权有效不等同于官方下载任务已验证；仍需解决正式任务调用通道，再对用户指定的单个文件做端到端测试。不能通过直接向官方应用数据库插入任务替代接口，也不应把普通直链 aria2 下载当作已验证的 NAS 加速链路。

## 补充验证：单文件转存与完整下载成功（2026-10-25）

用户提供分享链接并明确选择“完整下载这一个文件”。本次只处理 `kongq.mp4`，不创建订阅或定期扫描，不修改现有服务、账号绑定或其他下载任务。

### 真实执行结果

- 分享文件大小：`6,969,885,737` 字节，约 6.49 GiB。
- 转存源文件 ID：`566971587233800`。
- 调用分享 verify/list/transfer/taskquery，转存任务 `664178050815327` 返回 `success`，`succNum=1`。
- 目标云盘文件：`/CloudDock百度测试/kongq.mp4`，返回目标 ID `595506367920525`。下载严格使用此 ID。
- 官方 NAS 下载接口返回 `errno=0`、`succ_count=1`，任务 ID `21792924462000002`。
- 实际本地文件：`/vol3/1000/2T/飞牛影视/CloudDock百度测试/kongq.mp4`；属主 `1000:1001`。
- NAS 任务最终 `status=5`、`fail_code=0`、`current_size=size=6969885737`；临时下载文件已更名为最终 MP4，目录中只有该文件。
- 任务时间戳从 `1792924462` 到 `1792924571`，约 109 秒，平均约 63.94 MB/s（60.98 MiB/s）；过程中速度采样约 52–84 MB/s。此结果证明本次官方链路具有高速下载能力，不代表任何网络条件下都能达到线路上限。
- `ffprobe` 返回 0，识别 HEVC 视频 `3840×1608`、音轨和约 9625 秒时长。完成状态、字节数及媒体元数据验证通过；没有进行逐帧解码或与来源的标准 MD5 比较，分享返回的 md5 字段不是标准 32 位十六进制摘要。
- 官方应用自行同步了业务任务记录（`file_task.id=25`）；没有人工写入数据库。业务记录状态为 5，但其路径字段为空、缓存进度字节数曾滞后于 SDK，因此正式集成应维护自身路径映射并以 SDK 查询为进度依据。此次未通过网页逐项确认任务操作按钮。

### 已验证的下载调用通道

不依赖飞牛网页会话，NAS 本地进程读取官方应用现有 OAuth 和设备绑定，在内存中调用官方 HTTPS 接口：

`POST https://pan.baidu.com/rest/2.0/xpan/nas`

- 查询参数：`method=download`、现有 `access_token`/`device_id`、`type=2`、`rtype=1`、唯一数值 `rid`、`iot_version=FnOS-BaiduNetdisk-1.0.0`、`auto_sync=0`、`use_local_mtime=0`。
- 表单参数：`fs_ids` 为精确目标 ID 的 JSON 数组；`save_path=/vol3/2T/飞牛影视/CloudDock百度测试`。
- 进度查询：同一路径 `GET method=progress&type=2&status=0`，携带同一授权和设备，按返回的 `task_id` 匹配。
- SDK 虚拟路径 `/vol3/2T/...` 通过本机官方应用用户目录映射到宿主机 `/vol3/1000/2T/...`。该映射是本机实证，不能硬编码为所有 NAS 用户通用规则。

实际下载由正在运行的飞牛百度 SDK 执行，未使用 aria2。凭据没有输出或保存到验证文档；测试脚本只把非敏感任务状态存入 NAS `/tmp/clouddock-baidu-test-state.json`，避免重复提交。

### 对 CloudDock 后续开发的影响

端到端技术可行性已确认。后续可新增 NAS 本地适配器，将现有百度授权、精确分享转存、SDK 下载和任务查询串联起来；仍需开发 CloudDock 驱动、目录映射和 UI，当前产品尚不具备百度转存下载入口。SDK 接口属于应用内部使用的接口，应固定已验证版本并处理升级、令牌续期、幂等重试、失败恢复和权限隔离。

暂停/恢复、重启续传、令牌到期、多个文件、文件夹递归和并发任务尚未验证；此次成功不代表这些行为已完成产品验证。
